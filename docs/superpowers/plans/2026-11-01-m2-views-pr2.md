# M2 Views Implementation Plan (PR 2)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give wave 2's parameters and operations their faces: real Edit panels for the ring, the
grain's Smear and Quality and the buses' filters; the FX view's Delay and Limiter with a layout
that takes any number of panels; per-layer samples in both products, with drops on every lane;
the ring's splice marks, loop and capture on the Live lanes; the memory-cap readout. Then close the
PR 1 carry-over rows 312 to 338 that were left for PR 2. No audio changes.

**Architecture:**
- **The table still drives every panel** (`ui/src/EditLayout.cpp`). PR 2 adds three panels (Ring,
  Delay, Limiter), a `breakBefore` flag for a new line inside a panel (the Filter panel's two
  buses), and one shared panel grid that both the Edit and FX views lay out with (row 329).
- **The editor reaches sub-project 2's API only through `EditorContext`** (`ui/include/gg/ui/
  Editor.h`): per-layer sample load, relink, status and outline; the ring's metadata; the splice
  commands (`GigaGrainsPlugin::uiCommand`); capture and save (`MediaSession::captureRing`,
  `loadCapture`, `saveCapture`); collect; the memory cap. `EditorPlugin` fills them. `ui/` never
  includes a plugin header.
- **A Live lane spans its layer's ring.** It reads the length from `LivePeaks::frames()`, not
  M1's fixed 16 s, and it draws the splice marks, the selected splice and the loop window from
  `RingMeta`. A right-click, or Shift+F10 on the keyboard lane, opens the lane's menu: mark, clear,
  loop, capture to a layer, save a capture.
- **Undo** replays a whole-state entry in one batch through `sendValues` (row 337), and merges
  key-repeat nudges (row 323).

**Tech Stack:** C++23, CMake 3.22/Ninja, Catch2, JUCE through clap_juce_shim, sst-jucegui at
its pin (Knob, MultiSwitch, MenuButton, NamedPanel), `juce::PopupMenu`, `juce::FileChooser`
(async), `juce::FlexBox`.

**Spec:** `docs/superpowers/specs/2026-10-30-m2-views-design.md`. Read §6.1 (PR 2's list), §6.3

## Rulings this plan makes (recorded in the spec's §16 by Task 8)

The spec leaves these to PR 2's plan (§6.1: "each new ring operation a gesture mapped to
sub-project 2's API"). None of them departs from it.

| ID | Ruling |
|---|---|
| VW-P2a | The ring's operations are in a lane menu: a right-click on a lane, or Shift+F10 on the keyboard lane. It is not a drag vocabulary: a menu is discoverable, keyboard-reachable and testable headless. There is no "record" command: the ring records whenever it isn't frozen (the sources spec), so record is the Freeze toggle, and Loop and Overdub are parameters. |
| VW-P2b | Splice commands and captures are not undoable: they are commands, not parameters. Loop, chosen from the menu, is a gesture, so it is one undo entry. |
| VW-P2c | A file dropped on any lane loads into that lane's layer, in both products. A drop on a Live layer loads the sample and does not switch its Source, and the notice says so. |
| VW-P2d | A Live lane spans its layer's ring, `LivePeaks::frames() / sampleRate` seconds, falling back to 16 s when there are no peaks. |
| VW-P2e | The FX view's panels follow the signal chain: Delay, Reverb, Limiter, Output (Task 2 checks the order against `Processor.cpp`). The Edit view gains a Ring panel after Source, and the Filter panel puts each bus on its own line. |
| VW-P2f | The sample strip (`LoaderStrip`) follows the selected layer in both products: in Perform as M1's strip did, and in Edit as a full-width row under the layer strip. It holds the memory readout, the cap menu and Collect. Changing the cap is no undo entry: it is a setting. |

## Review Focus

1. **The editor on an inactive plugin** (no `Processor`). The lane menu's ring items are disabled.
   A capture says "the plugin isn't running". The memory readout still reads. Nothing is null-read.
   Tests: Task 4 (the context) and Task 6 (the menu).
2. **Ring Length changing under the lane.** The peaks are re-prepared and `frames()` changes
   between two frames. The span follows. A mark older than the span is not drawn. No peak is read
   past the strip. Test in Task 6.
3. **The cap lowered below what is in use.** The readout shows more used than the cap, for example
   "1.2 GB of 1 GB", in the notice color. Nothing is evicted. The next load is refused, with the
   status saying so. Tests in Tasks 4 and 7.
4. **A non-sample file dropped on lane B, or a drop during a load.** The first gives the
   not-a-sample notice. For the second, the latest request wins (the loader's rule) and no stale
   outline is drawn. Test in Task 6.
5. **A whole-state undo while the host doesn't drain.** Nothing is dropped, and the values arrive
   as the host drains. While the replay's slots wait, the header's undo is enabled; a second undo
   batches again. Test in Task 3.

  struct GestureOptions { bool nudge{false}; double timeSeconds{0.0}; };
  void beginGesture(gg::core::ParamSlot slot, float before, std::string label,
                    GestureOptions options = {});

- **The merge rule.** A nudge gesture is merged into the top entry when all of these hold:
  - nothing is waiting to be redone;
  - the top entry is a nudge entry on the same slot;
  - this gesture's begin `timeSeconds` is at most `kNudgeMergeSeconds` after the top's end.

  The merged entry keeps the top's `before`, takes the new `after`, and its end time moves on. A
  merge whose `after` equals the top's `before` removes the entry.
- **Snapshot entries** call `setValues` once, with every differing value, when `setValues` is set.
  Otherwise they fall back to `setValue` per slot. `EditorPlugin` sets `setValues` to
  `sendValues`.
- The nudge sites pass `{.nudge = true, .timeSeconds = juce::Time::getMillisecondCounterHiRes() /
  1000.0}`.

# M2 Views Implementation Plan (PR 1)

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give both plugins the four views INTENT §17 describes, on wave 1's parameters: a
Perform view with four lanes, a layer strip and an XY pad; a table-driven Edit view; a Mod view
with drag-to-route and depth rings; the FX view's reverb; undo/redo; two themes; keyboard
navigation; the About box; and the GPU spike's write-up, while every golden keeps its WAV hash.

**Architecture:**
- **One `GrainCanvas`, four lanes, one accumulator:** each lane is M1's lane for its own layer,
  typed by that layer's built kind, with pitch on the vertical axis; the resolve tints each lane's
  rows with the layer's colour. The lane maths stays in `gg-ui-core` (`LaneModel`, `PadModel`),
  framework-free and sanitizer-tested.
- **Every view is a table over `ParamIds.h`:** `EditLayout` places each slot in a view, a panel
  and an order; `ParamControl` is the one control adaptor (M1's `MacroValue` generalized), with
  rings for routes and a commit-on-release mode. A test fails on any slot no view places.
- **Two new main-thread → audio-thread paths, both by addition:** routes from the UI through a
  `LatestValue<ModRoutes>` on the plugin, and the per-lane publish fields in `UiSnapshot`.
  The undo stack (`gg-ui-core`, owned by `EditorPlugin`) replays through the gesture path.
- **The theme is a per-machine setting,** the notices are embedded at build time from the
  installers' license list, and `gg-snap` renders the views to PNG for the pack, CI and review.

**Tech Stack:** C++23, CMake 3.22/Ninja, Catch2, JUCE 9.0.4 through clap_juce_shim, sst-jucegui
at `22a89ca` (Knob, HSlider, VSlider, ToggleButton, MultiSwitch, MenuButton, NamedPanel,
MarkdownComponent, ModalBase, KeyboardTraverser, the light and dark style sheets),
sst-basic-blocks `ParamMetaData`, `gg-bench`.

**Spec:** `docs/superpowers/specs/2026-10-30-m2-views-design.md` (approved by the programme
manager 2026-10-30; the director's D1–D11 recorded, every recommended option). Read it before
your task; its sections are cited as "spec §n". The programme design
(`docs/superpowers/specs/2026-10-29-m2-programme-design.md` §6.6, §7) is the charter behind it.
This plan is PR 1 (spec §6.1); PR 2's tasks are written when wave 2 has merged.

## Global Constraints

**Non-negotiables** (CLAUDE.md; spec §4, §7):
- **The audio is bit-identical** with the editor open or closed, on any view, with any theme:
  the editor reaches the audio thread only through the plugin's UI queue (`uiBeginGesture`,
  `uiSetValue`, `uiEndGesture`) and the new route channel (Task 4). Nothing in `ui/` reads or
  writes an engine or `Processor` object except the publish structures through `EditorContext`.
- **Audio thread:** no allocation, locks, I/O or unbounded loops; RTSan-clean. The publish
  additions (Task 1) are plain fields filled from values the `Processor` holds; the route
  channel is a `LatestValue` of a fixed array.
- **No golden moves:** every one of the 36 cases keeps its WAV SHA-256, its metrics and its
  event log. A task that touches `core/` or `plugin/` runs `scripts/update-goldens.sh build/dev`
  before and after and states "every hash unchanged" in its commit (the list it prints).
- **No new parameter** (programme design §7.1). The theme, the selected layer, the chosen view
  and the undo stack are not parameters and are never saved in the state.
- **Ownership:** this sub-project owns `ui/`, `plugin/src/editor/`, `tools/gg-snap/` and
  `docs/spikes/m2-gpu-canvas.md`. Shared files only by addition: `core/include/gg/core/
  UiSnapshot.h`, `core/src/Processor.cpp` (the publish block), `core/include/gg/core/
  MachineSettings.h` and its `.cpp`, `plugin/src/GigaGrainsPlugin.h/.cpp`, `cmake/products.cmake`,
  `tools/gg-bench/`, `tests/CMakeLists.txt`, `.github/workflows/ci.yml`, INTENT. No edit under
  `libs/`. The header label `header.preset` keeps its component ID and its bounds slot and
  nothing else in the header's left group moves (sub-project 5 replaces its contents).
- **Component IDs** are the tests' handles: every parameter control is `param.<decimal CLAP ID>`
  (`"param." + std::to_string(gg::core::paramId(slot))`); the macros keep `macro.1` … `macro.8`
  and the strip's five IDs stay. The IDs this plan names are exact.
- **The layer palette** (D4) is Okabe–Ito: A `0xE69F00`, B `0x56B4E9`, C `0x009E73`, D
  `0xCC79A7`, as `gg::ui::kLayerTints` (Task 3); the letter accompanies the colour everywhere.
- **Dark by default** (D8); the lanes stay dark in both themes (D9); the window opens at
  960 × 600 and lays out from 640 × 360 (D11).
- **GUI tests are `#if defined(__APPLE__)`** inside `#if GG_BUILD_EDITOR`, as the existing ones
  in `tests/plugin/factory_tests.cpp`; framework-free tests (`[ui]`, `[core]`) run everywhere.
  Test case names are ASCII only. A new Catch2 case that measures time is tagged `[serial]`.
- **Formatting and commits:** `scripts/format.sh` before every commit; commits end with
  `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Run `cmake --build --preset dev`
  and the task's `ctest -L` labels before reporting a task done; the gate (`scripts/check.sh`)
  runs at the end of each wave and before the PR's review.
- **Worktrees:** tasks in one wave run in parallel worktrees (`git worktree add`, then that
  tree's `scripts/worktree-setup.sh --configure dev`), fast-forward merged into `m2-views` in
  task order; a task that adds a source to `ui/CMakeLists.txt` appends it at the end of the
  `gg-ui` list, and the later task resolves the conflict on rebase.

## Review Focus

Inputs the spec implies but no exit criterion names, most likely to bite first; each has its
test in the task that owns the code:
1. **The editor opened while the plugin is inactive** (publish pointers null): every view must
   draw from base values alone, the lanes their static parts, the pad and the strip usable, no
   null read. Test in Task 15 ("every view opens on an inactive plugin").
2. **A drop onto a full matrix** (48 routes in use): refused with a notice, no route lost.
   Test in Task 12.
3. **A snapshot with non-finite effective values** (a NaN Pitch after a bad host event): the
   ghost rectangle must not show and no capsule may escape its lane. Tests in Task 2.
4. **The settings file unwritable** (a read-only config folder): the theme switch still applies
   to this editor, the failure is reported in the header's notice, nothing crashes. Test in
   Task 6 and Task 15.
5. **Undo across a host's own move:** undo applies its `before` even if the host moved the value
   since; an empty stack's undo does nothing; a new entry clears redo. Tests in Task 5.

  struct WindowRect { float x0, x1, y0, y1; };                 // x0 ≤ x1, y0 ≤ y1 (y0 the higher pitch)
  WindowRect scanRect(const ScanRectValues &v, const LaneGeometry &g) noexcept;
  std::optional<WindowRect> ghostRect(const ScanRectValues &base, const ScanRectValues &effective, const LaneGeometry &g) noexcept; // any of the four > kGhostThreshold in its 0–1 domain; NaN never

  enum class DragAxis { Undecided, Horizontal, Vertical };

  void resolveToArgb(uint32_t *dst, uint32_t strideU32, std::span<const TintBand> bands) const noexcept; // rows no band covers resolve black; the one-band case equals the M1 overload bit for bit

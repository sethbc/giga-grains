# M3 Voice slice Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A layer at Mode Voice turns each note into a voice with its own grain stream, pitch, Env 1 amplitude, per-voice modulation and MPE or CLAP expression, spawning through its release; at Mode Cloud nothing moves.

**Architecture:** Voices live inside each layer's `Engine` as up to 16 extra `CloudScheduler` streams whose draws are merged by onset into the layer's one pool. The `Processor` owns an instance-wide note table (identity, pedal, expression) and per layer a voice allocator, steps each voice's Env 1 and Env 2 on the control grid, evaluates per-voice routes, and hands the engine each voice's `CloudParams`, pitch and amplitude envelope between pieces. The plugin and `gg-render` feed the new note fields and controls.

**Tech Stack:** C++23, CLAP 1.x, clap-wrapper (`clap_plugin_as_vst3`), Catch2, CMake presets, `gg-render` goldens.

**Spec:** `docs/superpowers/specs/2026-11-07-m3-voice-design.md` (parent: `docs/superpowers/specs/2026-11-07-m3-program-design.md`). The code survey behind the names below: the spec's research notes; file:line references are at `a3d5f2a`.

## Global Constraints

- Audio thread: no allocation, locks, I/O, syscalls or unbounded loops; RTSan-clean; 0- and 1-sample blocks; `params.flush` trivial.
- Determinism: randomness only from `gg::rng` keyed by (seed, layer, stream, field, index); no `std::` distributions; output bit-identical at any host block size; layers summed A to D.
- **Cloud at rest is bit-identical:** with every layer at Mode Cloud, MPE Off and no Voice-only route active, all 108 goldens keep their WAV SHA-256 (`scripts/update-goldens.sh` before and after; the baseline is `build/dev/golden/wav-sha256.txt` as of this branch's start).

- `rng::Key` and `rng::hash` do not change. A voice's draws use `stream = 1 + ordinal`.
- CLAP IDs are append-only; slots may shift. No new dependency.
- `-Wall -Wextra -Werror` (GCC 13 notes in CLAUDE.md: bounded accessors for `Count` sentinels, no `std::optional` in ternaries, `const auto &` structured bindings, one integer type across a conditional's arms).

## Review Focus

1. **A note-on and note-off in one control cell on a Voice layer:** a short voice that plays its release. Cloud's held set ignores it as today. (Task 5's `voice_grouping_short_tap`, Task 6's `processor_voice_short_tap`.)
2. **The 17th held note with the pedal down:** a pedal-held voice ranks as released and is stolen first. The stolen voice's grains finish their windows (no step in the output). (Task 6's `processor_voice_steal_pedal`.)
3. **Mode switched Voice to Cloud and back while notes sound:** every voice finishes at that boundary, Cloud resumes from the held set, nothing clicks, and the switch lands on the same sample at any block size. (Task 6's `processor_mode_switch_mid_note`.)
4. **A CLAP note expression for an unknown note ID, and a MIDI-MPE bend on a channel with no note:** both are ignored without touching another voice. A bend arriving before its note-on is kept as the channel's state and applies when the note starts. (Task 5's `note_table_expression_unknown_id` and `note_table_bend_before_on`.)
5. **Reset, deactivate/activate, or Layer On ramped off with voices sounding:** voices clear with the pool, at the sample Cloud grains clear, and `NOTE_END` is sent for each live note on reset. (Task 6's `processor_voice_reset` and Task 7's `plugin_note_end_on_reset`.)

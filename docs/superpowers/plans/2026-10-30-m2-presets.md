# M2 Presets and Content Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give both plugins a preset system (a `GGST` preset file, CLAP preset discovery and
`preset-load`, a browser, INIT, favorites, Mutate), a CC0 factory content pipeline (the content
repository's release, the fetch, the installers' Content component, the plugins' content search
path), `gg-render --preset`, and 48 voiced factory presets each with a golden render, while every
existing golden keeps its WAV SHA-256.

**Architecture:**
- **A preset is the session container** (`encodeState`'s bytes) with its name in PatchBase's
  `name` attribute and a `<preset>` element inside `PTCH` that every existing reader ignores;
  `gg/core/Preset.h` reads and writes it on top of `SessionState`. INIT is built in memory from
  the defaults. No chunk and no patch version is added.
- **Loading goes through the one state path:** `GigaGrainsPlugin::applyState` (factored out of
  `stateLoad`) applies values, routes and (for a session) the seed exactly as a restore does;
  `preset-load`, the browser and `stateLoad` all call it. The pinned clap-wrapper indexes our
  discovery provider and bridges it to VST3 program lists and AU factory presets; nothing in
  `libs/` changes.
- **The browser's catalog is the plugin's own** (`PresetCatalog`), scanning the same folders the
  provider declares, with favorites in a text file beside the settings. The content roots are one
  header-only resolver in gg-media (`ContentPaths.h`), shared by the plugins and `gg-render`.
- **Factory presets are JSON sources in `content/presets/`**, packed at build time by
  `gg-render --pack-preset` into `.ggpreset` files that `gg-products` stages with the fetched CC0
  samples as the installers' Content component. The samples come from the public content
  repository's tagged release, pinned by `content/pin.txt`.
- **Mutate is a pure function** in `gg/core/Mutate.h`, applied by the plugin as host gestures.

**Tech Stack:** C++23, CMake 3.22/Ninja, Catch2, clap and clap-helpers (`preset-load`, the
preset-discovery factory), sst-plugininfra PatchBase and tinyxml (private to gg-core), JUCE 9 and
sst-jucegui (the browser and the Mutate panel), nlohmann/json and CLI11 (`gg-render`), bash and
CMake scripts (the fetch, the installers), `gh` (the content release), `ffmpeg` and `flac` on the
director's machine (making the content release only; nothing enters the build).

**Spec:** `docs/superpowers/specs/2026-10-30-m2-presets-design.md` (approved by the programme
manager 2026-10-30; the director's D1–D9, every option 1). Read it before your task; its sections
are cited as "spec §n". The programme design
(`docs/superpowers/specs/2026-10-29-m2-programme-design.md` §6.5, §7.5, §7.8) is the charter
behind it.

## Global Constraints

**Non-negotiables** (CLAUDE.md; spec §4, §7):
- **Audio thread:** nothing new runs there. A preset load reaches it through the existing
  `loadedState_` and `SourceExchange` hand-offs; Mutate's values travel as editor gestures through
  `uiQueue_`. Keep `process` and `params.flush` RTSan-clean (`[plugin][rt]`).
- **Determinism:** Mutate's only randomness is `gg::rng::hash` of a `Key` (no `std::` distribution);
  `gg-render --preset` fills `setBases`, `setRoutes` and `setSourceNow` exactly as the spec's keys
  do, so block-size invariance and the event logs are untouched.
- **The audio is unchanged:** no DSP file is edited. Every one of the 36 goldens keeps its WAV
  SHA-256 at every task's end (`scripts/update-goldens.sh` before and after any task that touches
  `tools/`, `core/` or `plugin/`; the hash list in the commit).
- **State rules** (programme design §7.5): the container stays at version 1; no new chunk; no
  patch version bump; `<preset>` is an element under `<patch>` that old readers ignore;
  `SessionState` and `SessionState.h` change only by addition (two fields).
- **Stability:** no CLAP parameter is added or renumbered; the VST3 selector is clap-wrapper's at
  `0xC00000`; our IDs stay below `0xB00000`.
- **Ownership** (spec §4; the programme manager's notes): under `media/` only the new header-only
  `media/include/gg/media/ContentPaths.h`, nothing existing edited (not `media/CMakeLists.txt`);
  `Editor.cpp` changes only inside the `header.preset` slot (component ID and bounds kept, nothing
  else moved); `GigaGrainsPlugin.{h,cpp}`, `Factory.cpp`, `EditorPlugin.cpp`,
  `tests/CMakeLists.txt`, `cmake/products.cmake`, the installer scripts, `ci.yml`, INTENT and
  CLAUDE.md by addition; nothing under `libs/`; no new dependency.
- **Licensing:** every content file has a CC0-1.0 statement and a provenance entry (spec §6.5);
  no audio in this repository's history; `CC0-1.0.txt` joins the license set.
- **Carry-over policy:** 11 open rows at the start, none planned to close; 11 at the end; row
  87's pins re-run in Task 13.
- **Formatting and commits:** `scripts/format.sh` before every commit; test case names ASCII only;
  commits end with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`. Each task runs
  `ctest --preset dev` for its labels; the gate (`scripts/check.sh`) runs at the end of each group.
- **Subagents:** implementers on Opus (`model: "opus"`), reviewers inherit the parent model
  (the project's practice).

**The two groups** (spec §6.12). Tasks 1–13 are group 1 and need wave 1 alone: build them now.
Tasks 14–18 are group 2: they wait for the programme manager's word that wave 2 has merged and

**Names fixed here, used by every task:**

  (`gg/core/PresetInfo.h`); `kPresetExtension = ".ggpreset"`; `kInitLoadKey = "init"`; the tag

- `modeName(Mode)` is `"fx"` or `"instrument"`; `modeNamed(string_view)` the inverse.
- `GG_CONTENT_DIR` (environment: the first content root; CMake cache: a fetched folder).

## Review Focus

The spec implies these inputs but no task's tests exercised them until this list was written;
each has a test pinned to the owning task:
1. **A host's "load from file" hands the other product's preset** (an instrument preset to the
   FX): refused through `on_error` with "not a Giga Grains FX preset", and no value, route or
   name changes. Pinned in Task 6 ("the other product's preset is refused and changes nothing").
2. **A preset file at or past the 64 MiB cap, or with a `PTCH` nested past 64 levels:** refused
   without reading further or overflowing, as a state is. Pinned in Task 1 ("a preset past the
   cap or the nesting limit is refused") and Task 6 (the file path).
3. **No factory content installed and no user preset yet:** the provider declares no factory
   location, the catalog lists INIT alone, the browser's status line says what to do, and
   nothing throws. Pinned in Task 8 ("an empty machine lists INIT alone") and Task 10 ("the
   status line without content").
4. **A user preset name a file system refuses** (`/`, `\`, `:`, a leading dot, empty, 200
   characters): "Save as…" refuses it with a message or maps it to a safe file name, and never
   writes outside the user presets folder. Pinned in Task 8 ("a save name is made safe").
5. **A content-relative reference that escapes the root** (`../x.flac`, an absolute path, a
   backslash): never resolved. Pinned in Task 3 ("a reference that escapes a root is refused").

  Amount, Dry to Reverb);

# M1 FX Vertical Slice Implementation Plan

> **Erratum (2026-10-27, ruling M1-l):** Task 5 names `core/include/gg/core/Patch.h`. The PatchBase-derived Patch is internal (`core/src/Patch.h`), and the public API is `gg/core/PatchState.h`.

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Giga Grains FX on any track turns the track's audio into a Cloud texture. It has ten
automatable, modulatable parameters, saves its state, renders deterministically through
`gg-render`, and its audio path runs under ASan and RTSan.

**Architecture:**
- The engine stays framework-free. It gains a Cloud scheduler (replacing `PeriodicStream`) and a
  live ring source.
- A new JUCE-free library, `gg-core` (`core/`), holds:
  - the Patch (sst-plugininfra `PatchBase` + sst-basic-blocks `ParamMetaData`);
  - the parameter → engine mapping;
  - a `Processor` that runs the control grid, smoothing, the wet chain and dry/wet.
- The plugin and `gg-render` both drive that `Processor`.
- The plugin splits into a JUCE-free core and an editor layer (`GG_BUILD_EDITOR`), so the
  sanitizer presets build and test the plugin audio path.

**Tech Stack:**
- C++20, CMake presets, Catch2 v3;
- clap 1.2.10 + clap-helpers;
- sst-basic-blocks `ParamMetaData`;
- sst-plugininfra `PatchBase` with bundled tinyxml (new submodule);
- clap-wrapper and JUCE 9.0.4 only under `GG_BUILD_EDITOR`.

**Spec:** `docs/superpowers/specs/2026-10-27-m1-fx-slice-design.md`. Read it, plus `INTENT.md` §8, §14, §15, §18 and §19, and `docs/m1-carry-over.md`, before starting any task.

**Determinism** (INTENT §14)
- Randomness comes only from `gg::rng`, keyed by (seed, layer, stream, field, grain index), with real layer and stream IDs. Layer A = 0, stream 0.
- **No libm in any value that reaches the grain-event log.** Use `exp2Det` and `logDet`. `std::sqrt` is allowed: IEEE 754 requires it to be correctly rounded.
- **Parameter metadata uses literal default and bound constants**, never computed with libm at runtime.
- `-ffp-contract=off`; never fast-math.
- Grains are summed in spawn order.
- **The control grid is 32 samples, aligned to absolute sample positions:** a parameter or modulation event takes effect at the first multiple of 32 at or after its absolute timestamp.
- Output is bit-identical at any host block size (1, 7, 64, 511 and 4096, plus random splits).
- **Parameter values are floats** end to end: Patch, Processor and state. Incoming CLAP doubles are converted with `static_cast<float>` on receipt, so a saved and reloaded state renders identically.

**Audio thread**
- `Engine::process`, `Processor::process` and the plugin's `process`/`paramsFlush` never allocate, lock, do I/O or block. They're annotated `SST_CPPUTILS_NONBLOCKING`.
- They handle 0-frame, 1-frame and `numFrames > maxBlockSize` calls.

## Review Focus

These are the five inputs most likely to bite a user that no other task's tests would exercise. Each one is pinned by a test in the task named.

1. **An automation storm.** A host sends hundreds of parameter and modulation events in one block, several at the same sample. The expected result: no allocation or glitch, and the last event per parameter wins at its grid boundary. Task 6 tests this with `processor survives an automation storm`.
2. **Non-finite input.** NaN or ±Inf in the FX's input audio, which a broken upstream plugin can send. The ring stores 0 instead, and the output stays finite. Task 4 tests this with `live ring sanitizes non-finite input`.
3. **Corrupt, foreign or future state:**
   - truncated XML;
   - another patch's `id`;
   - unknown parameter IDs;
   - out-of-range values;
   - a newer `version`.

   Loading returns false, or clamps and ignores what it can't use. It never crashes, and the previous values stay untouched on failure. Task 5 tests this with `patch rejects or sanitizes bad state`.
4. **Freeze toggled rapidly.** It flips every control cell for a second, or stays on for a long time. The output has no discontinuity larger than the input's own steps, and it stays finite. Task 4 tests this with `rapid freeze toggling stays smooth`.
5. **Unusual FX wiring:**
   - the FX activated with a mono input, or with no input buffer;
   - deactivated and reactivated at 44.1, 96 or 192 kHz.

   Mono feeds both channels, a missing input is silence, and the ring and ramps resize with the sample rate. Task 7 tests this with `fx handles mono, missing input and new sample rates`.

### Task 4: Live ring source and freeze

**Files:**
- Create: `engine/include/gg/source/LiveSource.h`, `engine/src/LiveSource.cpp`

**Interfaces:**
- Consumes: `CloudScheduler`, `GrainDraw` (Task 3).
- Produces:
  ```cpp
  namespace gg {
  struct EngineConfig { ...; double liveSeconds{0.0}; };   // > 0 allocates a stereo ring of ceil(liveSeconds × sampleRate) frames
  enum class SourceMode { Sample, Live };
  void Engine::setSourceMode(SourceMode) noexcept;   // Live needs liveSeconds > 0; takes effect from the next process()
  void Engine::setFreeze(bool) noexcept;             // takes effect from the next process()'s first frame
  void Engine::process(const float *const *in, uint32_t numInChannels, float *const *out,
                       uint32_t numChannels, uint32_t numFrames) noexcept SST_CPPUTILS_NONBLOCKING;
  // the M0 overload process(out, numChannels, numFrames) stays and equals process(nullptr, 0, out, ...)
  }
  ```
  `LiveSource` is internal to the engine. Its contract, in ring time, is below.

  **Ring time.** `R(t)` is the number of frames written through output sample `t`.
  - Not frozen: one frame per sample.
  - Freeze on: the write gain ramps 1 → 0 over 20 ms while the head keeps advancing, then the head stops.
  - Freeze off: the head resumes at once and the gain ramps 0 → 1 over 20 ms. A toggle during a ramp continues from the current gain.
  - Non-finite input frames are written as 0. A mono input fills both channels; a missing input is silence.

  **Admission** (spec §6.3). The desired start is `s* = R(t0) − positionDraw × sr`. Clamp it to `[lo, hi]`:
  - Not frozen at `t0`:
    - `hi = R(t0) − 3 − M − max(0, dur × (rate − 1))`
    - `lo = R(t0) − N + 1 + M + max(0, dur × (1 − rate))`
  - Frozen at `t0`:
    - `hi = R(t0) − 3 − M − dur × rate`
    - `lo = R(t0) − N + 1 + M`

  If `lo > hi`, drop the grain and count it in `droppedGrains()`.

  **Head-proximity fade.** Applied per output sample, for read position `p(t) = start + elapsed × rate`:

  `g = clamp((R(t) − 1 − (p + 2)) / M, 0, 1) × clamp(((p − 1) − (R(t) − N)) / M, 0, 1)`

  When `g == 0`, the taps aren't read at all, so stale data and NaN can never contribute. This is the spec's 256-sample head-crossing crossfade: it fades any grain that a freeze makes approach the stopped head.

  using ParamValues = std::array<float, kParamCount>;
  struct WetParams { float levelGain; float mix; bool freeze; };
  CloudParams toCloudParams(const ParamValues &effective) noexcept;   // the mappings in Global Constraints; gain = 1/sqrt(max(1, densityHz × grainDurationSec))
  WetParams toWetParams(const ParamValues &effective) noexcept;
  float softLimit(float x) noexcept;   // |x| <= 0.5 → x; else sign(x) × (0.5 + 0.5 × z/(1 + z)), z = (|x| − 0.5)/0.5
  enum class Mode { Instrument, Fx };
  struct ProcessorConfig { double sampleRate; uint32_t maxBlockSize; uint64_t seed; Mode mode; };
  struct ParamEvent { uint32_t offset; ParamSlot slot; bool isModulation; double value; };   // offset within this process() call; sorted by offset
  class Processor {
  public:
      static constexpr uint32_t kControlGrid = 32;
      explicit Processor(const ProcessorConfig &);   // allocates; FX: liveSeconds 16 and SourceMode::Live; instrument: SourceMode::Sample with no source
      void setBase(ParamSlot, float) noexcept;       // immediate (flush outside process, state); clamped to range; Mix/Level jump with no ramp
      float base(ParamSlot) const noexcept;
      void process(const float *const *in, uint32_t numInChannels, float *const *out, uint32_t numOutChannels,

      void reset() noexcept;

  **How `Processor::process` handles events, ramps and the wet chain:**
  - An event at absolute `a = clock + offset` targets the boundary `b = ceil(a / 32) × 32`.
  - Pending values are kept per slot, separately for base and modulation; the latest event wins.
  - Rendering is split at every boundary that has a pending change. At each boundary:
    - the effective values become `clamp(base + mod)`;
    - the engine gets `setCloudParams(toCloudParams(...))` and `setFreeze(...)`;
    - the Mix/Level ramp targets update.
  - A boundary beyond this call's end carries over to the next call. Since only one boundary can be pending past the end, one per-slot array suffices.
  - **The wet chain is `engine wet × level (ramped) → softLimit → mix with dry`.**
  - The instrument outputs only the wet signal.
  - The whole call runs inside one `gg::ScopedDenormalsOff`.
  - Channels beyond 2 are zeroed.
